# Grant compliance checklist

More proposals fail on technicalities than on merit: a missing attachment, an extra page, a late upload, an expired
registration. Build a checklist from the solicitation, then verify the draft against it item by item. This is a review
aid; the authorised organisational representative remains responsible for the submission.

## 1. Build the requirements register from the RFP

Read the entire solicitation (RFP, NOFO, guidelines, FAQ, and any amendments — amendments override the original).
Extract every "must/shall/required/will not be considered" into a register:

| ID | Requirement | Source (page/section) | Type | Status | Evidence / location in draft |
| --- | --- | --- | --- | --- | --- |
| R1 | Applicant is a 501(c)(3) or public agency | NOFO §C.1, p.12 | Eligibility | ? | |
| R2 | Project narrative ≤ 10 pages, 12-pt font, 1" margins, double-spaced | §D.2, p.18 | Format | ? | |

**Types** to sweep for:
- **Eligibility**: entity type, geography, size/budget, prior grantee restrictions, cost share, one-application limits.
- **Registrations** (US federal): active SAM.gov registration with a UEI, Grants.gov account with AOR role; state
  vendor registration; these take days to weeks, so flag immediately if not current.
- **Structure**: required sections, their order and headings, character limits per field in online portals.
- **Format**: page limits (and what counts toward them), font, spacing, margins, file type, file naming, file size.
- **Attachments**: budget form, budget narrative, letters of support/commitment, resumes/bios, IRS determination
  letter, audit/financials, board list, logic model, org chart, indirect rate agreement, certifications.
- **Content requirements**: elements reviewers must find (e.g. "describe sustainability", "include a data management
  plan", specific performance measures).
- **Scoring criteria**: the rubric with points per section — map each criterion to where the draft answers it.
- **Deadlines**: LOI, questions, submission (date, time, **timezone**), and whether it's received-by or submitted-by.
- **Submission mechanics**: portal, who must submit, signature requirements.

## 2. Verify the draft

For each requirement: `met`, `partially met`, `not met`, or `n/a`, with the exact location in the draft (section/page)
as evidence. "Met" without a location is not accepted.

Check mechanically where possible:
- Page counts after export to PDF (the format reviewers see), not in the editor.
- Character counts for portal fields, including spaces, if the portal counts them.
- Numbers that appear in multiple places (request amount, people served, dates) agree everywhere.
- Section headings match the RFP wording so reviewers can find each criterion.
- Every attachment exists, is signed/dated where required, and is named per instructions.

## 3. Scoring alignment

For each scored criterion, note: points available, where it's addressed, and a weak/adequate/strong judgement with one
sentence on how to strengthen. Sections worth the most points deserve proportionate space.

## 4. Output

1. **Blocking issues** (would cause rejection): eligibility gaps, missing required attachments, over page limit,
   registrations not active, missed deadlines.
2. **Requirements register** (table above, fully filled).
3. **Scoring alignment table**.
4. **Pre-submission timeline**: working back from the deadline — final internal review (−5 days), registrations
   verified (−10 days or earlier), letters of support received (−7 days), upload by (−2 days; portals slow down near
   deadlines).
5. **Assumptions / questions for the funder** (submit through the official Q&A channel before its cutoff).

## Pitfalls

- Working from an old version of the RFP and missing an amendment.
- Assuming references, tables or appendices don't count toward page limits — check the counting rules.
- Treating "should" or "encouraged" items as optional when they appear in the scoring rubric.
- Letters of support that are generic or dated for another application.
- Planning to submit on deadline day.
